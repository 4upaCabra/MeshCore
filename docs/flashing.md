# Прошивка south_edition (v1.18.0b1)

Пошаговое руководство: какой файл выбрать, как прошить плату на ESP32, nRF52 и RP2040, что
настроить после первого запуска и что делать, если прошивка не встала.

Готовые файлы лежат в выпусках на GitHub:

- компаньон — [companion-v1.18.0b1](https://github.com/Alohataiti/MeshCore/releases/tag/companion-v1.18.0b1);
- репитер — [repeater-v1.18.0b1](https://github.com/Alohataiti/MeshCore/releases/tag/repeater-v1.18.0b1);
- комнатный сервер — [room-server-v1.18.0b1](https://github.com/Alohataiti/MeshCore/releases/tag/room-server-v1.18.0b1).

> Официальный веб-флешер MeshCore (flasher.meshcore.io) ставит прошивку основного проекта, а не эту
> сборку. Файлы south_edition берите из выпусков выше и прошивайте способами, описанными ниже.

## 1. Выберите прошивку

### Роль узла

| Роль | Выпуск | Для чего |
|---|---|---|
| Компаньон (`companion_radio`) | companion | узел, к которому подключается приложение MeshCore на телефоне или компьютере |
| Репитер (`repeater`) | repeater | ретранслятор без приложения: стоит на высоте и пересылает пакеты |
| Комнатный сервер (`room_server`) | room-server | общий чат-комната для группы |

### Вариант компаньона

Имя файла: `<Плата>_companion_radio_<вариант>-v1.18.0b1-<хэш>.<расширение>`.

| Вариант | Что внутри | Когда брать |
|---|---|---|
| `_ble` | BLE и USB, а на ESP32 с достаточным флешем ещё и WiFi. Канал связи с приложением переключается на ходу, без перепрошивки | **почти всегда** |
| `_usb` | только USB | если для платы нет `_ble` или нужен только кабель |
| `_wifi` | только WiFi с зашитой сетью | для стационарных узлов в WiFi |

Отдельных сборок `_uni`, `_ps` (энергосбережение ESP32) и `_async` (асинхронный e-ink) больше нет:
энергосбережение и асинхронный e-ink уже входят в `_ble` там, где плата их поддерживает.

Исключения этого выпуска:

- **LilyGo T-Beam 1W** и **LilyGo TLora V2.1** — только `_usb`: образ `_ble` не помещается во флеш;
- **ThinkNode M5** — `_ble` без энергосбережения, иначе образ не помещается;
- **Wio-E5 mini** — компаньона в этом выпуске нет: прошивка не помещается в 256 КБ флеша.

### Тип файла

| Платформа | Файл | Чем прошивать |
|---|---|---|
| ESP32 / ESP32-S3 / ESP32-C3 | `…-merged.bin` | полный образ с адреса `0x0` — для первой прошивки и при переходе с другой прошивки |
| ESP32 / ESP32-S3 / ESP32-C3 | `….bin` (без `merged`) | только программа с адреса `0x10000` — обновление поверх этой же сборки |
| nRF52 (T114, RAK4631, ProMicro/Faketec, T-Echo и др.) | `….uf2` | перетащить на диск загрузчика |
| nRF52 | `….zip` | DFU через `adafruit-nrfutil` или nRF Connect |
| RP2040 (Pico W) | `….uf2` | перетащить на диск `RPI-RP2` |
| STM32 (Wio-E5) | `….bin` / `….hex` | STM32CubeProgrammer |

Настройки, контакты и ключ узла при обычной прошивке **сохраняются**: и `merged.bin` с адреса `0x0`,
и UF2/DFU на nRF52 не трогают область данных. Чтобы начать с чистого листа, сначала полностью сотрите
флеш (раздел 5).

## 2. ESP32 / ESP32-S3 / ESP32-C3

Heltec V3, V4, WSL3, Wireless Paper, Wireless Tracker, Vision Master E213/E290, T-Beam, Xiao S3/C3 и
другие платы на ESP32.

### 2.1. В браузере (Chrome / Edge)

1. Откройте [ESP Tool от Espressif](https://espressif.github.io/esptool-js/).
2. Подключите плату кабелем с передачей данных, нажмите **Connect** и выберите порт платы.
3. В строке Flash Address укажите `0x0` и выберите файл `…-merged.bin`.
4. Нажмите **Program** и дождитесь окончания.
5. Нажмите на плате **RST** (или переподключите кабель).

### 2.2. Из командной строки (esptool)

```bash
pip install esptool
esptool.py --chip auto --port COM10 --baud 921600 write_flash 0x0 Heltec_v3_companion_radio_ble-v1.18.0b1-31d7c07-merged.bin
```

- В esptool 5.x команда пишется через дефис: `esptool --port COM10 write-flash 0x0 …-merged.bin`.
- Вместо `COM10` — ваш порт (`/dev/ttyUSB0` или `/dev/ttyACM0` в Linux, `/dev/cu.*` в macOS).
- **Не добавляйте `--flash_mode qio`**: образ собран в режиме DIO, с QIO плата уходит в цикл
  перезагрузок.
- Обновление поверх этой же сборки — файл без `merged` с адреса `0x10000`.

### 2.3. Если порт не открывается

У плат с «родным» USB ESP32-S3 (E213, E290, Wireless Tracker, V4) прошивка может не обслуживать USB, и
порт выдаёт «занят» или «устройство работает неправильно». Тогда переведите плату в загрузчик вручную:

1. Зажмите **BOOT** (USER).
2. Нажмите и отпустите **RST**.
3. Отпустите **BOOT** — плата появится как новый порт.
4. Прошейте. После окончания нажмите **RST**: в режиме загрузчика плата сама не перезапускается.

## 3. nRF52

Heltec T114, RAK4631, ProMicro / Faketec, nice!nano, LilyGo T-Echo, Seeed T1000-E, Xiao nRF52 и другие.

### 3.1. Перетаскиванием UF2 (проще всего)

1. Подключите плату по USB.
2. **Дважды быстро нажмите RST.** В системе появится съёмный диск загрузчика (его имя зависит от
   платы; внутри лежат файлы `INFO_UF2.TXT` и `CURRENT.UF2`).
3. Скопируйте на этот диск файл `….uf2`.
4. Диск сам отключится, плата перезапустится с новой прошивкой.

### 3.2. DFU по последовательному порту (adafruit-nrfutil)

Удобно, если кнопки RST нет под рукой или плата в корпусе.

```bash
pip install adafruit-nrfutil
# перевести плату в загрузчик: открыть порт на скорости 1200
python -c "import serial,time; s=serial.Serial('COM16',1200); s.close(); time.sleep(3)"
# загрузчик может появиться на ДРУГОМ порту — проверьте список портов
adafruit-nrfutil --verbose dfu serial -pkg Heltec_t114_companion_radio_ble-v1.18.0b1-31d7c07.zip -p COM9 -b 115200 --singlebank
```

Признак успеха — строка `Device programmed.`

## 4. RP2040 (Raspberry Pi Pico W)

1. Зажмите **BOOTSEL** и подключите USB — появится диск `RPI-RP2`.
2. Скопируйте на него `….uf2`. Плата перезапустится сама.

## 5. Полное стирание (сброс к заводскому)

Сотрите флеш, если узел ведёт себя странно после перехода с чужой прошивки или нужно начать с нуля.
**Будут удалены ключ узла, контакты, каналы и все настройки** — узел получит новый идентификатор.

- **ESP32:** `esptool.py --port COM10 erase_flash` (в esptool 5.x — `erase-flash`), затем прошейте `…-merged.bin` с адреса `0x0`.
- **nRF52:** через CLI командой `erase` в режиме CLI Rescue (раздел 7) либо прошивкой стирающей утилиты
  для вашей платы, затем обычная прошивка.

## 6. Первый запуск

### 6.1. Подключение приложения

- **Плата с экраном:** при старте на экране показывается PIN Bluetooth (`Pin:…`). Введите его в
  приложении при сопряжении.
- **Плата без экрана:** PIN по умолчанию — `123456`.
- **По кабелю:** выберите в приложении подключение по USB/Serial.

Если после перепрошивки телефон долго подключается или не подключается, удалите узел в настройках
Bluetooth телефона («Забыть устройство») и выполните сопряжение заново.

### 6.2. Частота вашего региона

Сразу после первой прошивки установите параметры радио для своей страны: в приложении (Settings →
Radio) или командой `set radio …`. Работа на чужой частоте нарушает местные правила.

### 6.3. Канал связи с приложением

Сборки `_ble` могут работать по BLE, USB и (на ESP32) WiFi. Режим меняется без перепрошивки:

- на экране: Настройки → Связь → Интерфейс;
- командой: `set comms ble`, `set comms usb`, `set comms wifi`; текущий — `get comms`.

В режиме USB Bluetooth выключается. WiFi-сети задаются командами `wifi add <сеть> <пароль>`,
`wifi list`, `wifi status`.

## 7. Новые настройки этой сборки

Полное описание экрана, меню и команд — в [руководстве пользователя](user-guide.md).

Команды вводятся в CLI приложения (раздел «Командная строка» / TerminalCLI), по USB в CLI Rescue
(удержание кнопки в первые 8 секунд после включения) или удалённо по PIN.

### 7.1. Порог отключения по батарее

Одно напряжение служит и блокировкой загрузки, и выключением во время работы:

```
set pwrmgt.shutdown 3300    # порог в мВ; 0 или off — выключено (по умолчанию)
get pwrmgt.shutdown
get pwrmgt.bootmv           # напряжение при последней загрузке
get pwrmgt.bootreason       # почему узел перезагружался или выключался
```

На компаньоне с экраном то же самое — Настройки → Система → «Откл. по АКБ».

| Аккумулятор | Ориентир порога |
|---|---|
| Li-ion / LiPo | 3000–3300 мВ |
| LiFePO4 | 2800–2900 мВ |
| LTO | 1900–2000 мВ |
| Натрий-ион | около 2000 мВ |

Как это работает:

- ниже порога узел при включении не загружается, а сразу уходит в глубокий сон;
- во время работы напряжение проверяется раз в 10 секунд; после 6 замеров подряд ниже порога (около
  минуты) узел засыпает. Короткая просадка при передаче не считается;
- после такого выключения для загрузки нужен порог плюс 150 мВ, чтобы узел не «моргал» у самого
  порога;
- **nRF52** (с управлением питанием) просыпается сам, когда напряжение поднимется примерно до 3,9 В,
  или при подключении USB. Аккумуляторы LiFePO4, LTO и натрий-ион до 3,9 В не заряжаются, такие узлы
  включаются от USB или кнопкой сброса;
- **ESP32** просыпается по таймеру раз в 30 минут и проверяет батарею заново.

Если узел питается от модуля заряда, который сам отключает нагрузку (например на 3,4 В), ставьте порог
чуть выше этого напряжения — тогда узел уснёт аккуратно, раньше модуля.

> Компаньон больше не выключается сам при 3,4 В, как раньше: по умолчанию порог выключен, задайте его,
> если нужна защита.

### 7.2. Энергосбережение ESP32

Настройки → Система → «Энергосбер.» или `set power.mode <режим>`:

| В меню | Команда | Поведение |
|---|---|---|
| Авто | `auto` | спит между событиями; пока к USB подключён компьютер — не спит (по умолчанию) |
| Выкл | `off` | без сна: максимальная отзывчивость, около 120 мА |
| Мягкий | `conservative` | спит, только пока приложение не подключено |
| Макс | `aggressive` | как «Авто», но просыпается реже: экономнее, отклик чуть медленнее |

В режимах связи WiFi и USB плата не спит ни в каком режиме.

### 7.3. Удалённый CLI по PIN

Команды узлу можно отправлять из приложения и личным сообщением с любого узла, зная PIN:

```
get cli.pin                 # PIN этого узла (8 шестнадцатеричных знаков)
set cli.pin new             # сгенерировать новый
set remote.cli pin          # режим: pin | flag | both | off
set remote.cli.fav on       # отправитель с верным PIN становится избранным
```

Верный PIN открывает сеанс на 10 минут. После 5 неверных попыток отправитель игнорируется 10 минут.

## 8. Если что-то пошло не так

| Признак | Что делать |
|---|---|
| ESP32 после прошивки бесконечно перезагружается | прошивали с `--flash_mode qio` — прошейте `merged.bin` заново без этого параметра |
| ESP32-S3: порт «занят» / «устройство работает неправильно» | загрузчик вручную: BOOT + RST (раздел 2.3) |
| ESP32-S3: после прошивки экран не оживает | плата осталась в загрузчике — нажмите RST |
| nRF52: после двойного RST диск не появляется | нажимайте быстрее; проверьте, что кабель передаёт данные |
| nRF52: `adafruit-nrfutil` не находит устройство | загрузчик появился на другом порту — посмотрите список портов заново |
| Узел не загружается от батареи | задан порог отключения выше напряжения батареи: подключите USB и `set pwrmgt.shutdown 0` или нужный порог |
| Телефон долго подключается после перепрошивки | «Забыть устройство» в Bluetooth телефона и сопряжение заново; на ESP32 для проверки — «Энергосбер.» → Выкл |
| Нет нужной платы в выпуске | см. исключения в разделе 1 или соберите прошивку сами (`pio run -e <окружение>`) |
